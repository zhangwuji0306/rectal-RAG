# 数据合规与发布清单

## D4 公共 CI 与目标仓库

代码候选范围见 [allowlist](发布范围-allowlist.txt)。从待审提交提取允许的文件到隔离目录，用仅包含这些文件的干净 Git 检出运行 `python tests/release_scope.py --verify-checkout --output <new-directory>`。该入口按 Git 索引固定文件集和 blob，拒绝与 Git 检出内容不符的工作树，然后用同一份 blob 字节扫描和生成输出。Git 配置的检出换行转换可以通过核对。诊断只显示计数、规则、文件序号和行号。唯一 PDF 例外是核定的合成小样。拟分发历史须另行核对实际 tree 和提交范围。

| Required check | 执行入口 |
|---|---|
| `public-unit` | `tests/run_public_tests.py --check unit` |
| `public-integration` | `tests/run_public_tests.py --check integration` |
| `public-schema-validation` | `tests/run_public_tests.py --check schema-validation` |
| `public-index-integrity` | `tests/run_public_tests.py --check index-integrity` |
| `public-retrieval-regression` | `tests/run_public_tests.py --check retrieval-regression` |
| `public-secret-scan` | `tests/release_scope.py --verify-checkout --output <new-directory>` |

工作流 `.github/workflows/public-ci.yml` 使用 `windows-2022`、Python `3.12.0` 和 `requirements.lock` 中的直接依赖版本。公共测试的分组见 `tests/suite_scope.py`。schema 和索引使用临时 SQLite/Chroma，检索在合成排名、qrels 和查询替身上验证。测试列出 skip/not-run 和原因；本机历史、原件保留和私有验收另行记录。真实 Chroma、模型、Gold、人工标签和运行原件只用于获授权的本机验收。

总控须先确认目标仓库、授权与待分发历史。仓库管理员在核准的干净提交上触发 Actions，通过 workflow run 及关联 commit 的 check runs 核实六个实际名称、GitHub Actions 来源和结论。随后在目标仓库的 `main` 分支保护规则中启用合并前 required status checks，把这六项绑定到 GitHub Actions 来源。读取 `main` 的保护设置并用受保护 PR 验证完成条件；使用 merge queue 时一并验证 `merge_group` 检查。记录目标、commit、run 链接和配置核验结果。当前本机 `origin` tracking ref 只反映上次获取的记录。

## 本地数据边界

`index/chroma_db/` 及 staging 库包含向量、元数据和正文块，只作为本机私有运行数据，不经 Git、Git LFS、发布压缩包或备份镜像公开分发。`corpus_raw/`、`normalized/`、`converted/`、`mucinous/`、`papers/`、上游 PDF corpus、生产 SQLite 和本地备份不属于默认代码发布物。

文献 metadata 和状态导出须按实际字段检查后再纳入发布；文件被称为 metadata、Gold Set 或 source.json 不意味着其中的正文摘录、私有路径与 provenance 均可公开。公开测试采用合成、可发布的 fixture。

## 来源与外传

来源通道不能替代许可证记录，缺失许可保持 unverified。默认获取策略使用已批准官方 OA 通道，非 OA 既有审批边界和 TLS 校验要求保留。

项目正文不自动发送到外部转换或生成服务。MinerU API adapter、DeepSeek/API key 的存在不构成外传许可；外部调用须有明确允许的数据范围。本地检索、内部使用与公开再分发是不同范围。

## 本机历史与清理

D-R4 已从索引取消跟踪部分原始全文、运行数据库、批量元数据、运行报告和驱动文件，磁盘原件保留。本机 Git tree 和历史仍含排除项，分发只使用从待审提交提取并核对的 allowlist 候选。新增 ignore 规则不会从索引或历史移除已跟踪文件。具体清理路径、跟踪裁定和历史核查保存在本机评审记录中。

## 公共测试入口与本机验收

```powershell
.venv/Scripts/python.exe tests/run_public_tests.py
.venv/Scripts/python.exe tests/run_local_acceptance.py
```

在干净分发候选中运行公共入口。公共测试报告跳过及未运行项目，依据 `tests/suite_scope.py` 区分公共和私有模块。本机验收依赖真实索引、模型及 Gold 等私有输入，仅在获授权的私有环境执行，分别记录实际结果。

## 发布前处理

1. 从已核定的提交按 allowlist 提取候选，核对实际目录、文件类型和内容，再运行公共测试。
2. 发布归档取自通过扫描的输出目录。若分发包含 Git 历史，另外核对目标仓库和拟分发提交范围。
3. 对批准取消跟踪的具体文件保留磁盘原件，按需添加 ignore 规则。远端发布与改动规则须取得对应权限。
